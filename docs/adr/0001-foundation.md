# ADR 0001: adopt a narrow MIT bridge foundation

Accepted 2026-10-02. Evaluated source, license, tests, package contracts and history handling of snowan/dsh-claude-plugin and daveycodez/dsh-llm-agent-bridge. The former has raw JSON Schema MCP forwarding, exact tool ID correlation, bounded process cleanup and substantive regression tests. The latter explicitly leaves DSH compaction/history synchronization incomplete. Reuse the former bridge foundation, preserving MIT notices and regression assertions; implement subscription routing separately. Neither package's prior verification establishes this derivative's compatibility.

Public DSH 0.2.0-rc.2 uses first-class tool-role messages, optional identity on one-shot request messages, a leading system-role prompt, ToolCallId, and width/height image targets. Migrate fixtures and adapter projection to those real types. Installation must only insert the provider; it must not change the selected model. Tests that formerly expected selection changes now assert preservation. Tests that expected failure on a system-prompt edit now require a new query with the changed prompt. These are documented product changes, not weakened acceptance.

Keep DSH peers external and use its official PluginPackages runtime resolution; bare Node resolution outside the running host is not equivalent to DSH's runtime. Prefer portable canonical cold rebuilds to potentially unsafe SDK resume across accounts. Warm queries remain active between normal turns. Cold replay is a user-role context envelope, not identical native role semantics. Persist bindings and ledger metadata with node:sqlite; no new native addon. One local writer is enforced, NFS unsupported. A crashed writer requires deliberate recovery; do not silently break a live lock.
