# Changelog

## Unreleased

Re-login a Claude account from the failure row, the settings screen, or `/claude-login`. The failure row shows 公式ログインを開始 for that account, and other failures still show their message and code. The login child runs against a staging directory with `BROWSER=true`, and the saved credentials are replaced only after the organization matches. A ready account keeps serving during the browser wait. The code wait is 15 minutes, with キャンセル and もう一度ログイン on the card. A matching profile in the other pool is marked ready when that pool's database is free. `default` leaves the live `CLAUDE_CONFIG_DIR` unset until the verified file is installed.

A non-zero `claude auth status` that prints JSON with `loggedIn: false` now reports `SUBSCRIPTION_LOGIN_REQUIRED` and names the account alias or profile path. Broken output, a launch failure, and a timeout keep their existing codes. The public message does not include command output.

A session whose pinned account is missing or `DISABLED` moves to another ready account when no tool call is unfinished, through the same migration used for a confirmed usage limit. A suspended account, an account that still needs login, and an unfinished tool call stay where they are.

A hung `claude auth status` now reports `AUTH_STATUS_TIMEOUT`. The 15-second SIGTERM limit let the CLI trap the signal and exit 0. Node then resolved `execFile` with empty stdout, and `JSON.parse` reported `AUTH_STATUS_INVALID_OUTPUT`. The check kills the process with SIGKILL, waits 45 seconds, and runs the command once more after 200 milliseconds. Only a timeout is retried. The failure record includes `startedAt` plus the elapsed time and the stderr byte count. Stderr text is not stored.

Report why the official login check failed. `AUTH_STATUS_UNAVAILABLE` is replaced by `AUTH_STATUS_TIMEOUT` (the 15-second limit stopped `claude auth status`), `AUTH_STATUS_COMMAND_FAILED` (it did not start, exited non-zero, was signalled or overflowed its output buffer) and `AUTH_STATUS_INVALID_OUTPUT` (its stdout is not a JSON object). A logged-out profile now reports `SUBSCRIPTION_LOGIN_REQUIRED`; `SUBSCRIPTION_AUTH_REQUIRED` remains for a login that is not claude.ai first-party. A relative profile path reports `PROFILE_MUST_BE_ABSOLUTE` instead of an unavailable status. The usage record evidence keeps the underlying error as a cause and adds the elapsed time, exit code, signal and stdout/stderr byte counts; stderr text is still not stored. Evidence stack locations are now read only after the exception message, so a message that quotes stderr lines shaped like stack frames no longer reaches the stored chain. A doctor `sdk.startup` failure now names the exception type and code.

Repair reproducible Claude Code protocol stops. Reconcile completed tool inputs with the SDK's Unicode normalization while retaining the original streamed arguments for DSH execution and preserving ID/name/input mismatch checks. In the managed bridge, keep an unavailable tool outside DSH and continue only after the SDK returns its explicit `No such tool available` error receipt; remap subsequent SDK block indices so the corrected MCP call survives DSH assembly. Omit an elapsed retry delay instead of sending zero, which DSH rejects as an invalid failure. Native tools remain disabled and unconfirmed tool effects still stop the request.

Verification on 2026-10-11: 28 recorded Unicode failures failed against the installed implementation and passed against the candidate, including MCP boundary correlation and unchanged emitted arguments. Real DSH LlmRuntime/SDK/CLI tests reproduced the bare-name stop before the change and passed recovery, a no-op tool receipt, a provider restart, and a Unicode tool round trip after it. Only no-op test tools ran; long-term operation and external service availability are not guaranteed by these checks. Reproduce with `scripts/live-protocol-recovery.mjs --live --state <confirmed-state> --report <private-report>`.

Record why a request failed. A failed attempt now stores payload-free evidence in its usage record in `state.sqlite`: the public failure code, the request phase, each exception in the cause chain as a name, an optional code and up to five stack locations, the kind and time of the last SDK event, and the exit code and signal of the Claude process when it had exited. Exception messages, prompts, tool arguments and stderr are not stored. A failure without a stable code still reports `SUBSCRIPTION_PROVIDER_FAILED`, and its message now names the exception type, the first stack location and the usage record ID. A cleanup failure no longer replaces the first failure: the provider returns the original code when disposing the bridge rejects, and the bridge keeps a protocol failure when closing the SDK query throws. Debug diagnostics include the same cause chain. These diagnostic changes initially used mocked-bridge verification; the protocol verification above also exercises failed real-account requests.

Continue a session after DSH prunes old tool output. The provider then rebuilds the conversation as one replay frame that carries every retained image. That frame now accepts up to 100 images, which is the Claude request limit, instead of the 20-image DSH upload limit for a single message. When a replay still exceeds 100 images or the DSH image byte budget, the provider fails the request with `IMAGE_OFFLOAD_REQUIRED` and the count of oldest images to offload. DSH records a durable offload and retries, where the turn previously ended with `CLAUDE_UNSUPPORTED_INPUT`. Images that DSH marked as offloaded reach Claude as placeholder text that names the attachment and its read-only path.

Real-account verification on macOS with `opus`: replay frames of 29 and 100 images completed and the model identified the first and last image; frames of 20 and 21 images that include a 2400-pixel image completed; a 101-image frame returned `IMAGE_OFFLOAD_REQUIRED` with `offloadImages: 1` before any model call (`pnpm test:live:image-replay`). A packed tarball installed into a temporary `dsh headless` profile completed a cold resume in which the harness logged the rejected attempt, an `image/offload` event, and a successful retry whose placeholder path resolved to the stored PNG (`pnpm test:live:image-offload`). A single new step that carries more than 100 images still fails with `CLAUDE_UNSUPPORTED_INPUT`.
