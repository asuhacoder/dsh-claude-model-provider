# Changelog

## Unreleased

A `writer.lock` left by a process that crashed or was killed no longer blocks every Claude turn. Before, any new writer failed with `STATE_IN_USE` until someone ran `doctor --recover` or deleted the file. Now, when the lock already exists, the writer runs the same checks as `doctor --recover`. The PID in the lock must be a positive integer, the system must report it as gone (`ESRCH`), and the lock must still name the same owner when it is read again. Only then is the lock removed and taken. A live PID, a PID owned by another user, an unreadable or invalid lock, or a lock that changed owner still fails with `STATE_IN_USE`.

A process that exits normally releases its `writer.lock`, also when it never closed the provider. Before, the lock was released only when the state store was closed, so a host that exited with code 0 left a lock that named its dead PID. A process stopped by a signal still leaves its lock, and the next writer now takes it as above. Closing a store whose lock file is already gone no longer throws.

`doctor --recover` reports `NO_STALE_LOCK` and exits 0 when there is no lock to remove, for example on a second run. Before, it failed with `COMMAND_FAILED`. A lock whose PID is owned by another user now reports `STATE_IN_USE` instead of `COMMAND_FAILED`, and the lock stays.

A turn no longer fails with `CLAUDE_PROTOCOL_ERROR` when Claude Code loses the API stream mid-response and sends the request again inside the same turn. Before, the blocks of the cut-off response were still counted, so the recovered turn failed reconciliation or reused a block index. Now a response that ended without a stop reason is set aside when the next one starts. Its streamed text stays in the DSH stream but leaves reconciliation, and block indices count the whole turn. If the cut-off response had streamed part of a tool call, the turn still fails with `CLAUDE_PROTOCOL_ERROR`, because DSH already holds that call and cannot withdraw it.

A model fallback ends the turn as `CLAUDE_MODEL_REFUSAL` even when the fallback block has no trigger. Claude Code rebuilds the block without its trigger, so the translator threw a `TypeError` instead. The refusal category is taken from the trigger only when the trigger is a refusal.

## 0.1.0-next.10 — 2026-11-13

A real Claude model id, such as `claude-fable-5-2`, works when Claude Code lists that model only under an alias. Claude Code 2.1.322 lists Fable 5.2 only as `fable`, and the same applies to `claude-opus-5-5`, `claude-sonnet-5-5` and `claude-haiku-5-5`. Before, such an id failed with `CLAUDE_INVALID_MODEL`, because only listed names were accepted. Now an id that no account lists is matched against the `resolvedModel` that Claude Code reports for each listed row, and the request uses that row. Model info, routing and the default model setting all use this match. An id that no row lists or resolves to still fails with `CLAUDE_INVALID_MODEL`.

A suspended account becomes ready again by itself when the suspension is lifted. Before, the background model list refresh skipped suspended accounts, so the account stayed suspended until a manual **Verify connection**. Now the refresh also reads suspended accounts whose list is more than 6 hours old. If the read succeeds for the same subscription, the account returns to ready, as after **Verify connection**. If the account is still suspended, the next request on it marks it suspended again. If the read fails, the account stays suspended and is retried after 15 minutes.

The plugin builds against DSH 0.2.2-rc.2. That release types the `LlmError` constructor to DSH's built-in failure codes, so the plugin's error class now casts its own code at that one call, as `LlmError.fromFailure` does. Behavior is unchanged, and the plugin's failure codes stay the same. Development checks now use DSH 0.2.2-rc.2. The peer and engines ranges are unchanged and still stop below `0.3.0-0`.

## 0.1.0-next.9 — 2026-11-11

A session pinned to an account that no longer offers its model or effort continues on another account that offers it, for example after the pinned account lost `opus` because of a payment problem. Before, every turn of that session failed with `MODEL_CAPABILITY_UNAVAILABLE`, because waiting cannot bring the model back and the session never moved off its pin. Now the session moves to an account that offers the model in a new generation, and the history is sent again as a replay. If that account is busy or blocked by a usage limit, the turn waits, as a new session does. If no other account offers the model, the turn still fails with `MODEL_CAPABILITY_UNAVAILABLE`, also when the pinned account is blocked, which reported `BOUND_ACCOUNT_COOLDOWN` before. A session with an unfinished tool call stays on its pin.

An account blocked by a usage limit becomes usable again when Claude lifts the limit early, for example after a plan upgrade. Before, the stored reset time held every request until it passed, so no request could reach Claude to learn that the limit was gone. Now one real request goes through every 5 minutes as a probe. If Claude reports the window allowed, or the turn completes, the block is cleared. If Claude rejects it again, the block stays and takes the new reset time. `providerRetryAfterMs` now points at the next probe instead of the stored reset.

The saved official model list refreshes itself in the background, so a model Claude Code starts offering, such as Fable 5.2, appears in the picker and can be used without a plugin update or **Verify connection**. Before, the list was read only at login and on **Verify connection**, and the router refused any model missing from it. Now, when DSH lists models, each ready, draining or cooling-down account whose list is more than 6 hours old is read again in the background, one at a time, without delaying the picker. The refresh writes only the model list and its metadata; aliases, state, quota windows and `verifiedAt` stay as they were. If the read fails, returns no models, or returns a different subscription, the last good list stays and that account is retried after 15 minutes. A model appears only once the installed Claude Code offers it for that account.

A failed turn keeps the DSH failure row with its heading, red indicator, and localized message. The plugin no longer registers the `turn-error` row. It adds the login panel under the turn only when the failure is `SUBSCRIPTION_LOGIN_REQUIRED` and names an account.

A verified login is committed only when its credentials reach the profile. On macOS, the Keychain item must be copied, because Claude Code reads it before the file. When that copy fails, the login reports `LOGIN_NOT_COMMITTED`, and the profile file goes back to its previous content. The account row and the other pool stay as they were. On other systems, a login that wrote no credentials file reports the same code instead of ready.

The Keychain copy sends the `security` command on stdin with `security -i` and passes the value as hex with `-X`. The value no longer appears in the process arguments.

## 0.1.0-next.8 — 2026-11-02

A tool call that passes an object to an untyped parameter, such as `input` on `cordis_inspect_query`, no longer stops the turn with `CLAUDE_PROTOCOL_ERROR` (partial and completed content did not reconcile). Claude Code 2.1.287 streams that object as a JSON string, then parses it back before it completes the message and calls the MCP tool. DSH now executes the parsed object Claude Code completed, so the tool receives an object, not a string. Only top-level values whose completed form is exactly the parse of the streamed string are accepted, and only when the completed block arrives before the stream stops, which is the order Claude Code uses. Any other difference still fails.

The settings page and login cards follow the DSH language setting in English and Simplified Chinese. Japanese is only in the README. With any other DSH language, those screens are in English. The README is in English, Japanese, and Simplified Chinese.

## 0.1.0-next.7 — 2026-10-31

Publish from a version tag. Pushing `v<version>` runs the release workflow, which checks that the tag matches `package.json`, that the version is a prerelease not yet on npm, that `CHANGELOG.md` has its section, and that the commit is on `main`. It then runs the full verification, publishes the exact rehearsed tarball to `next` with npm provenance through trusted publishing, and creates a GitHub prerelease with the tarball, the dry-run report and the SBOM. `latest` stays manual.

Re-login a Claude account from the failure row, the settings screen, or `/claude-login`. The failure row shows 公式ログインを開始 for that account, and other failures still show their message and code. The login child runs against a staging directory with `BROWSER=true`, and the saved credentials are replaced only after the organization matches. A ready account keeps serving during the browser wait. The code wait is 15 minutes, with キャンセル and もう一度ログイン on the card. A matching profile in the other pool is marked ready when that pool's database is free. `default` leaves the live `CLAUDE_CONFIG_DIR` unset until the verified file is installed.

A non-zero `claude auth status` that prints JSON with `loggedIn: false` now reports `SUBSCRIPTION_LOGIN_REQUIRED` and names the account alias or profile path. Broken output, a launch failure, and a timeout keep their existing codes. The public message does not include command output.

A session whose pinned account is missing or `DISABLED` moves to another ready account when no tool call is unfinished, through the same migration used for a confirmed usage limit. A suspended account, an account that still needs login, and an unfinished tool call stay where they are.

A hung `claude auth status` now reports `AUTH_STATUS_TIMEOUT`. The 15-second SIGTERM limit let the CLI trap the signal and exit 0. Node then resolved `execFile` with empty stdout, and `JSON.parse` reported `AUTH_STATUS_INVALID_OUTPUT`. The check kills the process with SIGKILL, waits 45 seconds, and runs the command once more after 200 milliseconds. Only a timeout is retried. The failure record includes `startedAt` plus the elapsed time and the stderr byte count. Stderr text is not stored.

Report why the official login check failed. `AUTH_STATUS_UNAVAILABLE` is replaced by `AUTH_STATUS_TIMEOUT` (the 15-second limit stopped `claude auth status`), `AUTH_STATUS_COMMAND_FAILED` (it did not start, exited non-zero, was signalled or overflowed its output buffer) and `AUTH_STATUS_INVALID_OUTPUT` (its stdout is not a JSON object). A logged-out profile now reports `SUBSCRIPTION_LOGIN_REQUIRED`; `SUBSCRIPTION_AUTH_REQUIRED` remains for a login that is not claude.ai first-party. A relative profile path reports `PROFILE_MUST_BE_ABSOLUTE` instead of an unavailable status. The usage record evidence keeps the underlying error as a cause and adds the elapsed time, exit code, signal and stdout/stderr byte counts; stderr text is still not stored. Evidence stack locations are now read only after the exception message, so a message that quotes stderr lines shaped like stack frames no longer reaches the stored chain. A doctor `sdk.startup` failure now names the exception type and code.

## 0.1.0-next.6 — 2026-10-17

Published to npm `next` from a local maintainer build, without provenance or a recorded source commit. The repository version stayed at `0.1.0-next.5`.

Repair reproducible Claude Code protocol stops. Reconcile completed tool inputs with the SDK's Unicode normalization while retaining the original streamed arguments for DSH execution and preserving ID/name/input mismatch checks. In the managed bridge, keep an unavailable tool outside DSH and continue only after the SDK returns its explicit `No such tool available` error receipt; remap subsequent SDK block indices so the corrected MCP call survives DSH assembly. Omit an elapsed retry delay instead of sending zero, which DSH rejects as an invalid failure. Native tools remain disabled and unconfirmed tool effects still stop the request.

Verification on 2026-10-11: 28 recorded Unicode failures failed against the installed implementation and passed against the candidate, including MCP boundary correlation and unchanged emitted arguments. Real DSH LlmRuntime/SDK/CLI tests reproduced the bare-name stop before the change and passed recovery, a no-op tool receipt, a provider restart, and a Unicode tool round trip after it. Only no-op test tools ran; long-term operation and external service availability are not guaranteed by these checks. Reproduce with `scripts/live-protocol-recovery.mjs --live --state <confirmed-state> --report <private-report>`.

Record why a request failed. A failed attempt now stores payload-free evidence in its usage record in `state.sqlite`: the public failure code, the request phase, each exception in the cause chain as a name, an optional code and up to five stack locations, the kind and time of the last SDK event, and the exit code and signal of the Claude process when it had exited. Exception messages, prompts, tool arguments and stderr are not stored. A failure without a stable code still reports `SUBSCRIPTION_PROVIDER_FAILED`, and its message now names the exception type, the first stack location and the usage record ID. A cleanup failure no longer replaces the first failure: the provider returns the original code when disposing the bridge rejects, and the bridge keeps a protocol failure when closing the SDK query throws. Debug diagnostics include the same cause chain. These diagnostic changes initially used mocked-bridge verification; the protocol verification above also exercises failed real-account requests.

Continue a session after DSH prunes old tool output. The provider then rebuilds the conversation as one replay frame that carries every retained image. That frame now accepts up to 100 images, which is the Claude request limit, instead of the 20-image DSH upload limit for a single message. When a replay still exceeds 100 images or the DSH image byte budget, the provider fails the request with `IMAGE_OFFLOAD_REQUIRED` and the count of oldest images to offload. DSH records a durable offload and retries, where the turn previously ended with `CLAUDE_UNSUPPORTED_INPUT`. Images that DSH marked as offloaded reach Claude as placeholder text that names the attachment and its read-only path.

Real-account verification on macOS with `opus`: replay frames of 29 and 100 images completed and the model identified the first and last image; frames of 20 and 21 images that include a 2400-pixel image completed; a 101-image frame returned `IMAGE_OFFLOAD_REQUIRED` with `offloadImages: 1` before any model call (`pnpm test:live:image-replay`). A packed tarball installed into a temporary `dsh headless` profile completed a cold resume in which the harness logged the rejected attempt, an `image/offload` event, and a successful retry whose placeholder path resolved to the stored PNG (`pnpm test:live:image-offload`). A single new step that carries more than 100 images still fails with `CLAUDE_UNSUPPORTED_INPUT`.
